# 병합 블록 표시 상한 설계

날짜: 2026-07-13
범위: FE 전용 — `mappers.ts` 병합 루프 + 매퍼 테스트만.
선행: `2026-07-08-consecutive-utterance-merge-design.md`. 그 스펙이 "장시간 단일
화자에서 문단이 과도하게 길어지면 표시 단위 제한을 후속 검토한다"고 명시한 후속이다.

## 문제

한 화자가 길게 말하면(예: 발표·강의) 연속 발화 병합이 수십 줄짜리 단일 블록을
만든다. 실사용에서 두 가지 가독성 문제가 확인됐다:

- **시각적 벽** — 줄바꿈 없는 텍스트 덩어리라 눈이 쉴 곳, 읽기 시작할 곳이 없다.
- **시간 기준점 상실** — 타임스탬프가 블록 첫 줄에 하나뿐이라 중간 내용이 언제
  나온 말인지 알 수 없고, 원하는 지점으로 점프하기도 어렵다.

## 결정 사항 (브레인스토밍 확정)

세 접근안(블록 재분할+이어짐 표시 / 블록 재분할·칩 반복 / 한 블록 내 문단) 중
**블록 재분할·칩 반복**을 선택했다. 구현이 가장 단순하고(UI 변경 없음, 매퍼만
수정) 각 블록이 거터 타임스탬프를 가져 두 문제를 모두 해결한다. 같은 화자 칩이
연속 반복되는 시각적 노이즈는 수용한다.

## 분할 규칙

`toMeetingDetail`의 병합 루프에 조건 하나를 추가한다:

- 다음 발화를 이어붙이기 전에 현재 블록의 `text` 길이를 확인한다.
  `last.text.length >= MERGE_MAX_CHARS`이면 이어붙이지 않고 새 entry를 시작한다.
- `MERGE_MAX_CHARS = 400` — 전폭 기준 약 3~4줄(문단 크기). 매퍼 내 명명 상수로
  두고 조정 가능하게 한다.
- 분할은 항상 발화(source) 경계에서만 일어난다 — 문장이 중간에 잘리지 않는다.
- 새 entry는 기존 생성 경로를 그대로 탄다. 따라서 불변식
  `id === sources[0].id`, `t === formatClock(sources[0].startMs)`이 자동 유지된다.
- 기존 병합 규칙(연속 같은 화자 · `status === "ok"`만 병합 · `transcribe_failed`는
  경계)은 변경 없음.

## 파급 효과 없음 (변경하지 않는 것)

- **점프·하이라이트·검색**: entry의 `sources`를 순회하므로 entry 수가 늘어나도
  로직 변경 없음. 분할된 각 블록의 "원문 보기"는 그 블록 첫 발화로 점프 —
  시간 기준점이 오히려 정밀해진다.
- **`tracks`·`spokenMs`**: 병합 전 `visibleUtterances` 기준 그대로.
- **UI 컴포넌트**: `Utterance`, `transcript-pane` 무변경.

## 엣지 케이스

- 400자를 넘는 **단일** 발화: 발화 내부는 쪼갤 수 없으므로 한 블록 유지(허용 예외).
- 판정이 "붙이기 전 현재 길이" 기준이므로 블록이 상한을 다소 초과할 수 있다
  (마지막으로 붙은 발화만큼). 의도된 단순화 — 정확한 상한이 아니라 문단 크기
  가이드다.

## 테스트

매퍼 유닛 테스트 (`mappers.test.ts`) 추가:

- 상한 초과 시 발화 경계에서 분할된다 — 분할된 각 블록이 불변식(첫 source의
  id·시각, sources 순서)을 지킨다.
- 상한 이내 병합은 기존과 동일하다 (기존 테스트 그대로 통과).
- `transcribe_failed` 경계 동작 불변.
- 400자 초과 단일 발화는 한 블록으로 유지된다.

페이지 테스트 (`meeting.test.tsx`): 기존 테스트 그대로 통과 (분할 블록 중간
발화 점프는 기존 sources 매핑 테스트가 커버).
