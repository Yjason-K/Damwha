# 대화 기록·검색 플랫폼 — 서비스 개념 정의서

> 상태: 초안 (v0.6, 초기 범위 설계 결정 완료) · 작성일: 2026-06-21 · 서비스명: 담화 (Damwha)

---

## 1. 한 줄 정의

**누가 언제 무슨 말을 했는지**를 화자 단위로 기록하고, 나중에 빠르고 정확하게 되짚어 찾을 수 있는 개인용 대화 기록·검색 플랫폼. 서비스명 **담화(Damwha)**가 원래 대화·이야기를 뜻하는 이름이며, 녹음 대상은 회의일 수도 인터뷰나 통화일 수도 그냥 대화일 수도 있다 — 파이프라인(7장) 어디에도 "회의"라는 전제는 없다.

녹취록을 텍스트로 쌓아두는 도구가 아니라, 모든 발언이 **화자 · 시점 · 원본 음성에 연결되어 추적 가능한** 형태로 정리되는 "개인 대화 기억 저장소"다.

---

## 2. 배경과 동기

대화는 계속 쌓이지만, 막상 "그때 그 얘기"를 다시 찾으려면 어렵다. 기억은 흐려지고, 녹취록은 길고, 원하는 대목은 어디 있는지 모른다. 이 서비스는 대화 내용을 **기록하고 · 정리하고 · 쉽게 찾는 것**을 출발점으로 한다.

부수적으로, 모든 발언이 원문·시점으로 추적되기 때문에 결정이나 약속이 나중에 흐려졌을 때 실제 발언으로 되짚는 것도 가능하다. 다만 이건 추적성이 주는 여러 효용 중 하나일 뿐, 제품의 중심은 아니다.

> 개인이 자신의 대화 기록을 관리하는 도구가 1차 목표다. 팀 분석/감시 도구가 아니다.

---

## 3. 목표 (Goals)

1. **기록** — 대화를 화자·시점이 붙은 구조화된 발언 데이터로 저장한다.
2. **정리** — 화자별·대화별로 정돈한다. 참석자와 함께 주요 주제·단락별 요약을 뽑는 층(기반층 — 모든 대화에 적용)을 두고, 그 위에 할 일·결정·약속 같은 유형별 추출(확장층 — 렌즈, 5.5·5.6)을 얹는다.
3. **검색** — 날짜 + 주제 + 참석자 + 발언 내용을 조합한 복합 검색으로 원하는 대목에 바로 도달한다.
4. **(부가) 추적** — 어떤 발언이든 원문·시점·오디오·맥락으로 되짚는다. 결정/약속 추적은 이 추적성 위에 얹히는 한 갈래일 뿐이다.

### 비목표 (Non-Goals) — 적어도 초기 버전에서는

- 팀 단위 협업 위키 / 실시간 공동 편집
- 구성원별 발언량·참석률을 집계하는 분석 대시보드 (감시성 기능)
- 회의를 "추궁"하기 위한 도구로의 포지셔닝

---

## 4. 핵심 컨셉 — 화자 귀속 발언 기록 + 추적성

이 서비스의 1급 객체(primary object)는 **발언(utterance)** 이다. 각 발언은 다음에 연결된다.

- **화자** — 누가 말했는가 (화자 식별로 자동 귀속)
- **시점** — 어느 대화, 몇 분 몇 초에 나왔는가
- **원문 + 원본 오디오** — 가공된 요약이 아니라 실제로 한 말
- **맥락** — 앞뒤 발언

검색·정리·되짚기는 모두 이 추적성 위에서 이뤄진다.

### 핵심 capability — 발언 점프

어떤 발언이든 → 정확한 그 순간(타임스탬프)으로 점프 → 원문 + 오디오 + 앞뒤 맥락을 확인한다. 이 메커니즘은 특정 유형(약속 등)에 한정되지 않고 **모든 발언에 공통 적용**된다. "그때 누가 뭐라고 했지?"를 실제 발언으로 되짚을 수 있게 하는 것이 제품의 본체다.

## 5. 핵심 기능 (Key Features)

### 5.1 자동 화자 식별 (Auto Speaker Identification)

최초 1회 화자 라벨링(프로필 등록)을 해두면, 이후 업로드되는 대화에서 성문(Voiceprint)을 추출해 자동으로 이름을 연결한다. 매번 "참석자 1"을 수동으로 고쳐야 했던 기존 STT 서비스의 페인포인트를 제거한다. 이 서비스에서 화자 식별은 **모든 발언을 사람에게 귀속**시키기 위한 기반 기능이다.

### 5.2 다차원 / 구조화 검색 (Semantic & Structured Search)

키워드 검색을 넘어 **날짜 + 주제 + 참석자 + 발언 내용**을 조합한 복합 검색을 지원한다.

- 예: "지난주 기획회의에서 김영재가 말한 UI 개선안 찾아줘"
- 결과: 해당 회의의 정확한 타임라인 위치로 바로 이동

### 5.3 원문 추적 / 발언 점프 (Traceability)

검색·정리 결과의 어떤 발언이든 클릭하면, 원문·화자·타임스탬프·오디오·앞뒤 맥락을 즉시 확인할 수 있다. (4장의 핵심 capability를 화면에서 구현한 기능)

### 5.4 화자별 타임라인 (Speaker Timeline)

대화 한 건을 화자 트랙으로 펼쳐 보여준다. 누가 언제 얼마나 말했는지 한눈에 보이고, 특정 화자의 구간만 따라가며 들을 수 있다.

### 5.5 모아보기 — 렌즈 (Lenses)

기록된 발언에서 특정 유형만 추려보는 **확장층**이다. "필요할 때 켜는 보조 뷰"가 아니라 **대화가 회의 성격일 때만 결과가 나오는 층**으로 둔다 — 잡담이나 사적인 통화를 녹음하면 할 일·결정 같은 게 애초에 나올 게 없으므로 추출 결과가 0건이고, 해당 섹션은 자동으로 사라진다. 이를 가리는 대화 유형(회의/인터뷰/통화 등) 필드는 두지 않는다 — LLM이 전사 내용을 보고 알아서 판단하며, 필드를 두면 새 UI·새 스키마·오분류를 고치는 경로까지 함께 끌고 온다.

**유형과 우선순위 (v1 기준)** — 1) 액션아이템, 2) 결정사항, 3) 약속/책임. 액션아이템을 최우선에 두고 약속/책임을 가장 뒤로 둔 것은, 제품 정체성이 "할 일·논의 내용의 정리"에 있고 약속 추적은 곁가지임을 반영한다. 우선순위는 곧 구현 순서 가이드다. 주제·키워드는 더 이상 렌즈가 아니다 — 대화 유형을 가리지 않고 모든 녹음에 나오는 기반층이라 요약(5.6)의 일부로 옮겼다.

**생성 방식 (AI 자동 추출)** — 셋 다 "발언을 유형으로 분류"하는 렌즈라 AI 자동 추출로 채운다. 사용자가 직접 만든 임의의 렌즈(저장 검색 기반)는 이 셋과 별개로 남겨둔 v1 이후 과제다.

**범위 (회의별 + 전체 둘 다)** — 같은 추출·인덱스 데이터를 회의로 필터링하느냐 마느냐의 차이.

- _회의별_ — 회의 1건의 우측 인사이트 패널, 요약 탭 안 블록으로 해당 회의의 렌즈만.
- _전체(전역)_ — 모든 회의를 가로지르는 렌즈 뷰 (예: "내 모든 액션아이템").

**추출 항목의 성질** — 자동 추출된 렌즈 항목은 막는 게이트 없이 바로 채워지되, 전부 사후 수정 가능하고 사용자가 직접 추가할 수도 있다(아래 8장 '추출 자동화' 결정). 따라서 각 항목은 출처(AI 추출 / 사용자 추가 / 사용자 수정됨)를 갖는다. 신뢰도는 차단 기준이 아니라 "확인 필요" 같은 **비차단 힌트**로만 쓴다. 수동 추가 항목은 원본 발언이 없으면 [증거] 점프가 비며, 필요 시 사용자가 발언을 연결한다.

### 5.6 대화 요약 (Conversation Summary)

기록된 발언에서 주요 주제와 단락별 요약을 뽑아내는 **기반층**이다. 렌즈와 달리 대화 성격을 가리지 않고 **모든 녹음에 적용**된다 — 회의든 인터뷰든 잡담이든, 발언이 있으면 요약이 나온다.

- **생성** — 로컬 LLM을 1회 호출해 주요 주제와 단락별 요약(제목 + 불릿)을 한 번에 뽑는다. 렌즈 추출과는 별도 잡으로 나란히, 독립적으로 돈다.
- **읽기 전용, 통째 재생성만** — 요약은 전사의 파생 뷰지 사용자가 직접 쌓아온 자산이 아니다. 항목 단위 수정은 제공하지 않고, 탭 헤더의 버튼 하나로 통째로 다시 만든다. 항목 편집을 허용하면 출처 컬럼·머지 규칙·충돌 처리가 뒤따르는데, 그건 렌즈 쪽(5.5)에서 이미 치른 비용이라 다시 치르지 않는다.
- **단락 시각의 출처** — 단락 경계의 시각은 LLM이 답하지 않는다. LLM은 단락 시작·끝 발화의 id만 지목하고, 실제 시각은 DB에 저장된 그 발화 행에서 가져온다. 모델이 타임스탬프를 지어내는 실패 모드를 원천 차단한다.

## 6. 화면 구조 (Layout)

홈은 **브라우즈 우선 셸 + 검색 항상 전면(browse-first shell, search always present)** 구조다. 앱을 열면 빈 검색창이 아니라 내 회의 목록이 펼쳐지고, 사용자는 훑어보며 알아본다(recognition). 동시에 검색은 별도 홈 화면이 아니라 어느 화면에서든 한 키로 호출되는 상시 기능으로 둔다. 특정 유형 모아보기는 그 위의 렌즈로 얹는다.

- **좌측** — 회의 / 폴더 목록 (프로젝트·날짜)
- **중앙** — 선택한 회의의 기록 (화자별 타임라인 + 발언)
- **우측** — 인사이트 패널. 탭은 `요약 / 파일 / 메모` 셋이고, 요약 탭 안에 참석자 · 주요 주제 · 다음 할 일 · 핵심 결정 · 단락별 요약이 이 순서로 쌓인다.
- **전역 (항상 전면)** — 상단 고정 검색바 + 커맨드 바(⌘K)로 어느 화면에서든 검색 호출. 빈 검색 홈을 강요하지 않으면서 시맨틱 검색을 한 키 거리에 둔다. 코퍼스가 쌓일수록 사용자의 무게중심이 브라우즈→검색으로 자연히 이동한다.

발언 점프는 검색 결과나 렌즈 어디에서든 원본 대화의 정확한 지점으로 이동하는 공통 동작이다. 렌즈는 두 위치에서 나타난다 — 회의별 렌즈는 우측 인사이트 패널의 요약 탭 안 블록(다음 할 일 · 핵심 결정)으로, 전체(전역) 렌즈는 좌측 내비에서 닿는 별도 모아보기 뷰로. 어느 쪽도 홈을 차지하지 않는다. 회의 그래프는 초기 범위에서 제외(향후 검토).

> 왜 브라우즈 우선인가: 검색 우선 홈(빈 입력창이 첫 화면)은 코퍼스가 없는 초기엔 빈 화면이 되고, 사용자가 무엇이 들어있는지조차 모른다. 브라우즈는 회의가 2개여도 작동한다. 검색 우선은 이미 검색할 게 많은 서비스(Perplexity 등)에서나 통하므로, 0부터 시작하는 개인용에는 브라우즈를 기본 자세로 두고 검색을 상시 보조로 얹는다.

## 7. 시스템 아키텍처 / 파이프라인

오디오 업로드부터 검색 가능한 기록까지의 데이터 흐름.

0. **앱 안 녹음 (선택)** — 워커 Mac의 마이크로 녹음하면서 전사·등록 화자 식별을 실시간 미리보기로 보여주고, 종료하면 아래 배치 파이프라인이 정본을 만든다.
1. **음성 활성 탐지 (VAD)** — 소음과 침묵을 제거한다.
2. **화자 분리 (Diarization)** — 오디오를 짧게 나누고 유사한 목소리끼리 클러스터링해 화자별 타임라인을 분리한다.
3. **화자 식별 (Identification)** — 성문을 벡터로 변환하고, 벡터 DB의 등록 화자와 코사인 유사도를 비교해 이름을 식별한다.
4. **음성 인식 (STT)** — Whisper 등으로 각 화자 구간을 텍스트로 변환하고, 화자·시점과 결합해 구조화된 JSON으로 만든다.
5. **구조화 / 인덱싱** — 발언 데이터를 검색용으로 인덱싱(키워드 + 의미 임베딩)한다. 업로드 시 결정·액션아이템 등 특정 유형을 자동 추출해 렌즈에 연결하고, 사용자가 수동으로 재추출할 수도 있다. 재추출은 비파괴적이어야 한다 — 사용자가 수정하거나 직접 추가한 항목은 덮어쓰지 않고 보존(머지)한다.
6. **요약** — 발언 데이터에서 주요 주제와 단락별 요약을 로컬 LLM 1회 호출로 뽑아 저장한다(5.6). 렌즈 추출과 나란히 독립된 잡으로 돌아가므로, 한쪽이 실패해도 다른 쪽에는 영향이 없다.

```
오디오 → VAD → Diarization → Identification(Vector DB / 코사인 유사도)
      → STT(Whisper) → 구조화 JSON → 검색 인덱싱(+ 선택적 유형 추출) → 요약 → 저장
```

> 이전 버전의 "약속 추출"을 **"구조화·인덱싱"** 으로 일반화했다. 약속/결정 추출은 인덱싱 이후의 선택적 단계(렌즈용)로 내려간다.

## 8. 핵심 설계 결정 / 열린 질문

### 결정됨

- **홈 구조** — 브라우즈 우선 셸 + 검색 항상 전면(⌘K + 상단 고정 검색바). 빈 검색 홈을 강요하지 않고, 코퍼스가 쌓이면 브라우즈→검색으로 무게중심이 이동하도록 한다. (코드 시작 전 확정)
- **렌즈 범위** — 유형 우선순위(액션아이템 > 결정사항 > 약속/책임), 생성은 AI 자동 추출, 범위는 회의별 + 전체 둘 다. 주제·키워드는 기반층 요약(5.6)으로 옮겼다. (상세 5.5)
- **추출 자동화** — 막는 게이트 없이 자동 반영 + 사후 수정. 추출은 업로드 시 자동으로 돌리되 수동 재추출 허용. 사용자는 내용·유형 수정에 더해 직접 추가까지 가능. 따라서 (1) 신뢰도는 비차단 힌트로만, (2) 항목마다 출처(AI/사용자) 표시, (3) 재추출은 비파괴적(사람 손댄 항목 보존). (상세 5.5 · 7장)
- **녹음 / 프라이버시** — 순수 개인용 전제로, 다른 참석자 성문 포함 전원 저장. 음성·성문 데이터는 로컬/자체 서버에만 보관, 녹음 고지는 두지 않음. 이 세 가지는 "데이터가 사용자 통제를 벗어나지 않는다"는 한 전제로 묶이며, 그것이 성문 저장의 법적 위험을 낮추는 근거다(개인정보보호법은 업무 목적 처리자를 주로 겨냥, 순수 사적·로컬 기록은 그 핵심 대상 밖 — GDPR 가사·개인활동 면제와 유사). **가드레일: 공유·내보내기가 그 전제를 깨는 유일한 경계선이므로, 내보내기/공유는 기본 비활성 + 의도적 마찰(확인·경고)로 처리.** (법률 자문 아님; 공유 단계로 확장 시 전문가 확인 권장)
- **대화 유형 필드** — 두지 않는다. LLM이 전사 내용을 보고 알아서 적응하고, 필드를 두면 새 UI·새 스키마·오분류를 고치는 경로까지 함께 끌고 온다. (5.5 · 5.6)
- **요약 화면 블록** — 주요 주제 / 다음 할 일 / 핵심 결정 / 단락별 요약 네 블록. 클로바노트류의 3블록 구성에 결정(핵심 결정)을 더했다 — 결정 블록은 결과가 없으면 자동으로 사라지므로 추가 비용이 거의 없다. (6장)
- **배치** — 새 화면을 만들지 않고 기존 우측 인사이트 패널의 요약 탭에 얹는다. 좌/중앙/우 3패널 구조는 그대로 유지한다. (6장)
- **단락 표시** — 기본은 접힘. 우측 레일 폭(320px)에서 단락 8개를 전부 펼치면 세로 길이가 1600px를 넘어 뒤쪽 단락에 닿기 어렵다. 시각(타임스탬프)과 제목만 한 줄로 나열하고, 클릭으로 펼친다.
- **추출 구조** — 요약과 렌즈(할 일·결정·약속)를 하나의 LLM 응답에 같이 담지 않고 별도 잡으로 완전히 분리한다. 로컬 LLM 런타임은 응답 스키마 강제를 신뢰할 수 없고 검증이 통째(all-or-nothing) 방식이라, 하나로 합치면 한쪽이 실패할 때 둘 다 날아간다. 대가로 LLM 호출이 2번으로 늘지만, 실패를 격리하는 쪽을 택했다.
- **수정 정책** — 읽기 전용 + 통째 재생성만. 요약은 전사의 파생 뷰지 사용자가 직접 쌓아온 자산이 아니다. 항목 편집을 허용하면 출처 컬럼·머지 규칙·충돌 처리가 뒤따르는데, 이미 렌즈 쪽에서 치른 비용이라 다시 치르지 않는다. (5.6)
- **용어 범위** — 코드 · DB · API의 `meeting` 용어는 그대로 둔다. UI 카피와 문서만 대화 중심으로 옮긴다. 사용자에게 보이지 않는 내부 용어 리네임이 릴리스를 막을 이유가 없다.
- **참석자 탭** — 삭제. 참석자 목록은 이미 요약 탭 맨 위 블록으로 남아 있어 별도 탭이 중복이었다. (6장)
