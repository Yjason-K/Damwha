# 녹음 중 입력 장치 복구 설계

**작성일:** 2026-11-02
**선행:** `main` @ `c754420`, 이슈 [#69](https://github.com/Yjason-K/Damwha/issues/69)
**대체:** 없음. `live-recorder.ts`의 `ended` 즉시 실패(`device_ended`) 동작을 바꾼다.

## 목표

녹음 중인 입력 장치가 사라져도 회의 내용을 잃지 않는다. 기본 입력으로 이어서 녹음하고 사용자에게 알린다.

## 원인

- Chromium은 녹음 중인 장치가 사라지면 트랙을 `ended`로 끝낸다. 기본 장치로 연 트랙도 새 기본 입력으로 옮겨 주지 않는다(2026-11-02 실측).
- 레코더는 `ended`를 받으면 곧바로 `device_ended`로 마감하고, 복구 경로가 없다.
- 이슈 제목과 달리 AirPods 연결이나 기본 입력 전환만으로는 끊기지 않는다.

## 범위

- `fe`: `ended`를 받으면 제약이 같은 기본 입력을 다시 열어 기존 `AudioContext`·Worklet에 잇는다.
- 사용자가 고른 장치가 사라져도 기본 입력으로 넘어간다. 사용자가 고른 동작이다(회의 내용 보존 우선).
- 다시 열기는 5초 상한, 1회다. 실패하면 지금처럼 `device_ended`로 마감한다.
- 알림: 화면은 토스트, 감지 카드는 `녹음 중` 아래 안내 문구.
- 다시 여는 공백은 PCM에서 빠진다. 경과 시간은 계속 가므로 2초를 넘으면 서버가 `capture_gap`으로 남긴다.

## 범위 밖

- `AudioContext` 출력 전환 때의 시계 멈춤(약 1.7초 측정). 재현 조건이 다른 문제다.
- `mtg_121`의 정확한 계기 규명.
- 원래 장치가 돌아왔을 때 되돌아가기.

## 완료 기준

- C1 기본 입력 녹음이 장치 분리 뒤에도 이어진다.
- C2 고른 장치가 사라져도 기본 입력으로 이어진다.
- C3 다시 열지 못하면 `device_ended`로 마감된다. 늦게 온 스트림은 닫힌다.
- C4 사용자가 멈춘 뒤 도착한 스트림은 닫히고 실패로 기록되지 않는다.
- C5 토스트와 카드로 알린다.
- C6 모달과 카드 시작 경로 모두 실측한다.
