# 메모·녹음 종료·화자 수정의 데이터 보존 설계

**작성일:** 2026-11-04
**선행:** `dev` @ `88d1aa29da078d90e3528ee6f95272a5a448bdbb`
**작업 브랜치:** `fix/issues-75-76-77-data-integrity`
**이슈:** #75, #76, #77
**대체:** 기존 설계를 대체하지 않는다. 세 경로의 순서·재시도·처리 버전 경계를 보정한다.

## 목표

최신 메모가 이전 저장에 덮이지 않고, 일시적인 종료 요청 실패 후 녹음을
다시 마무리할 수 있으며, 화자 수정이 과거 전사의 의미를 바꾸지 않게 한다.
사용자가 세 이슈의 수정, 작업 기록, dev 대상 PR 생성을 요청한 범위다.

## 범위와 결정

### #75 메모 자동저장

- 같은 회의의 메모 저장은 입력 순서대로 완료되도록 직렬화한다.
- 다른 회의의 저장은 독립적으로 진행한다.
- 이전 실패의 롤백이 이후 초안의 낙관적 캐시를 지우지 않게 한다.
- 언마운트·회의 전환 시 기존 flush 동작을 유지한다.
- API와 DB 스키마 변경 없이 동일 앱의 겹친 저장을 수정한다.
  서로 다른 앱/탭의 동시 편집 충돌 해결은 범위 밖이다.

### #76 라이브 종료

- 진행 중 종료 호출은 하나로 합치되 실패한 요청은 다시 시도할 수 있다.
- 마지막 오디오 조각과 바이트 경계는 서버 확인 전까지 보존한다.
- 서버가 이미 봉인했거나 응답만 유실된 경우 기존 오프셋 프로토콜을 따른다.
- 캡처 자원은 재시도 때문에 다시 열지 않으며 기존 중단·봉인 동작을 유지한다.
- 종료 응답이 없는 채 새 녹음을 시작하면 이전 종료를 먼저 재시도한다.
  재시도해도 확정되지 않으면 회의 상태를 조회한다. 서버가 종료 또는 삭제를
  확인한 경우에만 소유권을 놓고, 녹음 중이거나 조회할 수 없으면 꼬리를
  유지한다. 서버에서 받아들이지 못한 꼬리가 저장됐다고 표시하지 않는다.

### #77 클러스터 화자 수정

- 회의와 클러스터의 현재 처리 버전을 확인한 뒤 수정한다.
- 발화 수정은 해당 처리 버전에만 적용한다.
- 재처리와 수정의 경합에서도 오래된 클러스터로 새 버전을 바꾸지 않는다.
- 과거 발화·렌즈 근거와 기존 화자 등록·승격·음성 지문 처리를 보존한다.

## 범위 밖

리뷰의 나머지 이슈(#78~#86), 모델 변경, UI 재설계, 새로운 API 필드,
데이터 마이그레이션, 운영 데이터 변경, dev 병합은 포함하지 않는다.

## 완료 기준

- C1 겹친 메모 저장 뒤 서버와 캐시에 최신 입력이 남는다.
- C2 이전 저장 실패가 이후 초안을 지우지 않고 회의 전환 flush가 보존된다.
- C3 종료 실패 뒤 재시도가 실제로 전송되며 마지막 오디오가 보존된다.
- C4 종료 중복 호출·응답 유실·기존 봉인 경로가 오디오 중복 없이 동작한다.
- C5 화자 수정이 현재 처리 버전에만 적용되고 과거 발화는 유지된다.
- C6 오래된 클러스터/재처리 경합을 거절하고 정상 수정은 유지한다.
- C7 관련 회귀 테스트, 타입/빌드 검사, 실제 경계 QA와 PR 리뷰를 기록한다.
- C8 spec·plan·result와 이슈별 커밋을 남기고 dev 대상 PR을 생성한다.
