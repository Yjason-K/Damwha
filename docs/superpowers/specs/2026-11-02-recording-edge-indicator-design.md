# 회의 녹음 중 가장자리 알약 표시 설계

- **작성일:** 2026-11-02
- **선행:** 브랜치 `feat/recording-edge-indicator`, 기준 커밋 `eed396d8`(`origin/dev`, PR #68·#71 포함)
- **이슈:** [#70](https://github.com/Yjason-K/Damwha/issues/70)
- **대체:** 없음. `2026-11-01-meeting-detection-design.md`의 녹음 중 카드 동작만 이 문서가 바꾼다.

## 1. 목표

회의 감지 카드로 녹음을 시작하면 360×84 카드가 화면 위쪽 가운데에 회의가 끝날 때까지 남아 회의 화면을 가린다. 녹음이 시작되면 카드를 작은 알약으로 줄여 가운데를 비운다. 녹음이 이어지는 상태는 계속 보이게 하고, 멈출 경로도 남긴다.

### 비목표

- 시작 제안 카드 변경
- 녹음이 끊기는 문제(#69)
- 입력 레벨 파형
- 메뉴 막대(Tray) 항목
- 알약을 끄는 설정. 끄면 회의가 끝난 줄 알았는데 녹음이 이어지는 경우를 알아챌 수단이 없다.
- 모달 등 카드 밖에서 시작한 녹음의 표시

### 실패로 볼 것

- 알약을 조작했더니 회의 앱의 포커스가 빠져 단축키가 먹지 않는다.
- 호버가 깜빡여 `중지`를 누르기 어렵다.
- 평소에 `중지`가 보여 실수로 녹음을 끊는다.
- 저장된 위치가 화면 밖이라 알약이 보이지 않는다.

## 2. 동작

| 상황 | 동작 |
| --- | --- |
| 녹음 시작 | 카드가 화면 오른쪽 위 알약으로 바뀌고 상단 가운데가 비워진다. 저장된 위치가 있으면 그 자리에 뜬다 |
| 평소 | 빨간 점과 경과 시간만 보여 준다 |
| 호버 | 알약이 왼쪽으로 늘어나며 `중지`를 보여 준다. 오른쪽 끝은 고정한다 |
| 알약 본문 클릭 | 담화의 그 회의 화면을 연다. 사용자가 직접 누른 동작이므로 담화가 앞으로 나오는 것을 허용한다 |
| `중지` 클릭 | 지금 카드의 `중지`와 같이 녹음을 멈춘다 |
| 드래그 | 화면 안 어디든 옮기고 다음 녹음에도 위치를 유지한다 |
| 마이크만 녹음, 마이크 전환 | 카드로 펼쳐 `카드 복귀 시간` 동안 보인 뒤 알약으로 돌아간다(§4.5) |
| 끊김, 완료 등 끝 상태 | 지금처럼 위쪽 가운데 카드로 펼친다 |
| 자동 종료 | 그대로 둔다 |

## 3. 실측 근거

2026-11-02, Electron 44.3 일회용 스파이크. 전체 화면 Chrome의 Google Meet 위에서 사용자가 직접 조작했다. Zoom은 실측하지 않았다.

| 방식 | 호버 | 본문 클릭 | 드래그 | `중지` | 포커스 | 판정 |
| --- | --- | --- | --- | --- | --- | --- |
| `-webkit-app-region: drag` | 이벤트 없음 | 이벤트 없음 | 됨 | 호버가 없어 못 누름 | 누르면 `focus` 발생 | 탈락 |
| 포커스 가능한 패널 + 페이지 JS 드래그 | 됨 | 됨 | 됨 | 됨 | 누르면 `focus` 발생 | 제외 |
| **`focusable: false` 패널 + 페이지 JS 드래그** | 됨 | 됨 | 됨 | 됨 | `focus` 0건 | **채택** |

- 두 알약 모두 전체 화면 Meet 위에 보였고, 조작 뒤 Meet의 `⌘D`가 먹었다. 깜빡임은 없었다.
- leave 지연이 없을 때는 창 크기가 바뀌면서 `enter`·`leave`가 수십 ms 간격으로 반복됐다. leave를 200ms 늦춘 뒤로는 반복이 없었다.
- 표본은 사용자 1명, 맥 1대, 방식별 클릭·드래그 각 1~2회다.
- 화면 공유: `setContentProtection(true)`인 두 알약을 띄우고 Chrome의 Meet에서 공유했을 때 시크릿 창의 참가자 화면에 알약이 보이지 않았다. 사용자가 확인했고, 전체 화면 공유 캡처가 남아 있다.
- 포커스 가능한 패널도 `⌘D`는 먹었다. 그래도 `focus` 이벤트가 없는 쪽을 고른 것은 회의 앱의 키 입력을 건드릴 가능성을 없애기 위해서다.

## 4. 설계

### 4.1 창

- 지키는 설정: `type: "panel"`, `showInactive()`, `setAlwaysOnTop(true, "floating")`, `setVisibleOnAllWorkspaces(... visibleOnFullScreen, skipTransformProcessType)`, `setContentProtection(true)`.
- 알약은 `focusable: false`다. `show()`로 창을 앞으로 가져오는 경로는 여전히 두지 않는다.
- 스파이크의 알약은 둥근 모양을 위해 `transparent: true`, `hasShadow: false`에 1px 테두리를 썼다.
- `DETECT_CARD_SIZE` 고정을 없애고, 뷰에 따라 크기와 위치가 정해지게 한다. 카드는 지금 자리, 알약은 §4.4의 자리다.

스파이크 크기는 알약 92×32, 호버 144×32다. 1시간이 넘어 `1:02:34`가 되어도 잘리지 않아야 한다.

### 4.2 렌더러 → main 경로

§6.11에 새 예외를 만들지 않는다. preload와 IPC 없이, 지금처럼 페이지의 사건은 main이 건 `next()`의 반환값으로만 나간다. `parseDetectAnswer`는 새 모양을 받되 렌더러 데이터로 보고 검증한다.

| 사건 | main의 일 |
| --- | --- |
| 호버 시작·끝 | 창 크기를 바꾸되 오른쪽 끝을 고정한다 |
| 드래그 이동량 | 창을 옮긴다 |
| 드래그 끝 | 위치를 저장한다 |
| 본문 클릭 | 그 회의를 연다 |
| `중지` | 기존 `stop` |

- 4px 이상 움직여야 드래그로 본다. 그보다 적으면 클릭이다.
- leave는 200ms 늦추고, 그 안에 다시 들어오면 취소한다. 드래그 중에는 leave를 무시한다.

### 4.3 경과 시간

main이 녹음 시작 시각을 알고 페이지가 그 값으로 1초마다 표시를 갱신한다. 렌더러에서 값을 받는 경로는 없다. 카드로 펼쳤다가 알약으로 돌아와도 시간은 이어진다. `시작`은 `deps.start()`가 `started: true`를 돌려준 시점이다.

### 4.4 위치 저장

- `<userData>/detection-state.json`에 위치를 함께 저장한다. 파일이 없거나 값이 잘못되면 기본 위치를 쓰고, 기존 `enabled` 읽기는 깨지지 않아야 한다.
- 지금 `setEnabled()`는 파일 전체를 `{ enabled }`로 덮어쓴다. 저장 경로를 하나로 합쳐 `enabled`와 위치 어느 쪽을 쓰든 다른 쪽을 보존한다.
- 기본 위치는 커서가 있는 화면 `workArea`의 오른쪽 위이고, 여백은 오른쪽·위 각 12px이다.
- 알약을 띄울 때 호버 크기 전체가 어떤 화면의 `workArea` 안에 들어가지 않으면 기본 위치를 쓴다. 외장 모니터가 빠진 경우가 여기 해당한다.
- 녹음 중 화면 구성이 바뀌어 알약이 화면 밖으로 나가면 같은 규칙으로 옮긴다.
- 드래그 중에는 자유롭게 움직이고, 놓을 때 호버 크기 전체가 들어가도록 가장 가까운 화면의 `workArea` 안으로 밀어 넣은 뒤 그 값을 저장한다. 그래서 저장된 위치는 화면 구성이 그대로면 다음 녹음에서도 그대로다. (작성자 판단)
- 위치를 저장한 적이 없으면 녹음 시작 때 정한 기본 위치를 그 녹음이 끝날 때까지 쓴다. 카드에서 돌아올 때 커서 위치로 다시 계산하지 않는다. (작성자 판단)
- 녹음 중 펼치는 카드와 끝 상태 카드는 알약이 있는 화면의 위쪽 가운데에 뜬다. 사용자가 보는 화면에 경고가 떠야 하기 때문이다. 시작 제안 카드는 지금처럼 커서가 있는 화면에 뜬다. 알약을 띄우기 전에 끝나는 시작 실패 카드는 알약 위치가 없으므로 시작 제안 카드가 있던 자리에 그대로 뜬다. (작성자 판단)

### 4.5 상태

- 판단은 `app/meeting-detection.ts`에 둔다. `detect-view.ts`의 `recording`을 알약과 카드 두 표현으로 나눈다.
- `micOnly`·`micSwitched`는 녹음이 끝날 때까지 유지되는 이력이다. 펼침 여부는 이와 별도의 상태로 둔다. 알약 조건은 `recording`이고 펼침 상태가 아닐 때다.
- 경고가 새로 생기면 카드로 펼치고, `카드 복귀 시간` 뒤 알약으로 돌아간다. 이 시간은 기존 끝 카드와 같은 10초다. 복귀 뒤 알약에는 경고를 표시하지 않는다.
- 카드가 펼쳐진 동안 두 번째 경고가 생기면 카드 내용을 바꾸고 10초를 다시 잰다. (작성자 판단)
- 녹음이 끝나면 복귀 타이머를 취소한다.
- `recording`의 `open` 전이를 새로 둔다. 지금 `onCard()`는 `finished`에서만 `open`을 처리한다. 알약을 눌러 회의를 열어도 녹음과 알약은 그대로다. `meetingId`가 없으면 아무 일도 하지 않고 로그만 남긴다.
- 끝 상태 카드의 문구와 버튼은 지금 그대로다. 위치는 §4.4를 따른다.

### 4.6 화면

`desktop/shell/detect.html`에 알약을 넣거나 전용 페이지를 둔다. 어느 쪽이든 색은 `:root`와 다크 `@media` 블록에만 두고, 빨간 점 색도 토큰으로 둔다. 문구는 `textContent`로만 넣는다. 고치면 CSP 해시를 다시 계산하고 `tests/windows/shell-html.test.ts`로 확인한다. 알약 본문과 `중지`는 스크린 리더가 읽을 수 있는 이름을 가진다.

## 5. 빌더에게 맡기는 것

- 카드와 알약을 한 창으로 할지 두 창으로 할지. 카드는 지금 불투명 창과 시스템 그림자에 기대고 있어, 한 창이면 투명 창에서 카드 모양이 그대로인지 확인해야 한다. 시작 제안 카드의 모습과 동작은 바뀌면 안 된다.
- 경과 시간 문자열 형식의 구현과 알약의 정확한 너비
- 드래그 이벤트를 묶어 보낼지 여부
- `detection-state.json`의 위치 필드 모양

## 6. 작업 범위

주로 `desktop/`만 바꾼다. `desktop/CLAUDE.md`의 회의 감지 절과 데이터 위치 표도 고친다.

## 7. 완료 기준

1. 녹음이 시작되면 카드가 알약으로 바뀌고 상단 가운데가 비워진다.
2. 경과 시간이 보이고, 카드로 펼쳤다 돌아와도 이어진다.
3. 호버로 `중지`가 나오고 눌러서 멈출 수 있다. 평소에는 `중지`가 보이지 않는다.
4. 클릭하면 그 회의 화면이 열린다.
5. 옮긴 위치가 다음 녹음에도 유지된다.
6. 저장된 위치가 어떤 화면에도 맞지 않으면 기본 위치에 뜬다.
7. 마이크만 녹음, 마이크 전환은 카드로 펼쳐졌다가 알약으로 돌아오고, 끝 상태는 카드로 펼쳐진다.
8. 전체 화면 Chrome의 Google Meet 위에서 알약이 보이고, 호버·드래그·`중지` 뒤 Meet의 `⌘D`가 먹는다.
9. Chrome의 Google Meet 전체 화면 공유에서 참가자에게 알약이 보이지 않는다. 다른 회의 앱의 공유는 이 기준에 포함하지 않는다.
10. 시작 제안 카드의 모습과 동작은 그대로다.

`pnpm desktop` 테스트에 판단 로직(뷰 선택, 답 파싱, 위치 보정, 복귀 타이머)의 테스트를 더한다. 실측은 Zoom이 아니라 Chrome의 Google Meet으로 한다.
