## 1. 회귀 재현과 수정

세 경로는 수정 파일이 겹치지 않으므로 독립적으로 진행한다.
각 경로는 기존 테스트 구조 안에서 실패를 먼저 확인한 뒤 수정한다.

- #75: `fe/src/features/meeting/api/notes.ts`와 메모 테스트.
  저장 순서, 이전 실패의 롤백, 회의 간 독립성, 전환/언마운트 flush를 확인한다.
- #76: `fe/src/features/meeting/lib/live-recorder.ts`와 레코더 테스트.
  종료 실패 후 재전송, 꼬리 보존, 동시 호출, 서버 봉인을 확인한다.
- #77: `be/src/meetings/meetings.service.ts`, `meetings.repository.ts`,
  기존 클러스터 DB 테스트. 이전 버전 보존과 오래된 클러스터/재처리 경합을 확인한다.

- 관련 프론트엔드 테스트, 프론트엔드 빌드와 변경 파일 lint.

- 브라우저 메모 경로, 레코더 공개 API, HTTP 클러스터 수정의 실제 경계 QA.

- 실행하지 못한 검증과 기존 실패는 결과 문서에 구분해서 남긴다.
