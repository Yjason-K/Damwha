## 코드로 확인한 원인과 변경

### #102: 전사 단어 경계

MLX와 faster-whisper 어댑터가 단어별 `.strip()`으로 원래 공백을 지웠다.
align의 단어 결합·동일 화자 구간 병합과 live 미리보기는 공백을 새로 삽입했다.

두 어댑터의 `Word.text`에 원래 문자열을 보존하고, 조립 과정은 빈 구분자로
결합하도록 변경했다. align은 인접 구간을 합친 뒤 완성된 발화의 바깥 공백만
제거한다. live도 완성된 미리보기의 바깥 공백만 제거한다.
반복 환각 필터는 비교 키만 `.strip()`하여 첫 단어의 앞 공백 유무가 반복
판정을 바꾸지 않게 했으며, 보존하는 단어 문자열은 수정하지 않는다.

기존 한국어 테스트의 단어 입력은 새 내부 계약에 맞춰 원래 경계 공백을
포함하도록 변경했다. 기대하는 완성 발화와 화자 배정 결과는 유지했다.

### #103: 유효 발화가 없는 요약

현재 처리 버전의 `status='ok'`, `text IS NOT NULL` 발화가 0건이어도
요약 요청을 전송했다. 응답에 세그먼트가 있으면 `_map_indexes`가 빈 ID
목록을 참조하여 `IndexError`를 냈고, 잡은 미분류 TRANSIENT로 재큐잉됐다.
핸들러는 발화 조회 전에 모델 서버도 시작했다.

발화가 있을 때만 요약 콜백을 실행하도록 변경했다. 서버 시작·종료,
소유권 상실 중단 훅, 디스크 부족 감시는 핸들러의 해당 콜백에서 수행한다.
빈 입력은 기본 `SummaryResponse`를 기존 공통 저장 경로로 넘긴다.
`topics`, `segments`, `suggested_tags`는 빈 배열, 요약 상태는 `done`,
잡 진행률은 100이 된다. 기존 요약·오류도 정상 저장 규칙에 따라 교체된다.
DB 소유권·처리 버전 가드와 잡 페이로드는 변경하지 않았다.

기존 빈 요약 테스트는 세그먼트 없는 가짜 클라이언트를 사용해 요청 전송과
인덱스 오류를 놓쳤다. 이를 실제 잡 디스패치·Postgres·HTTP 응답 대역을 쓰는
`tests/test_empty_summary.py`로 옮기고 강화했다. 발화 자체가 없는 경우와,
다른 버전·NULL 텍스트·전사 실패 발화만 있는 경우를 포함한다.

## 검증 범위와 남은 한계

- STT 테스트는 모델 출력 대역과 실제 Postgres를 사용했다. 실제 일본어·중국어
  오디오의 인식 정확도, CER/WER, 처리 시간·메모리 개선은 측정하지 않았다.
- 실제 LLM이 빈 프롬프트에 세그먼트를 생성하는 빈도는 측정하지 않았다.
  해당 응답 형태를 주입하면 기존 코드에서 `IndexError`가 나는 것은 재현했다.
- 제품 경로 밖의 기존 진단 스크립트 `scripts/run_whisper.py`,
  `scripts/eval_stt.py`, `scripts/bench_stt_batching.py`는 공백을 삽입하는
  별도 출력 조립이 남아 있다. 이번 검증은 이 스크립트의 출력에 의존하지 않았다.
- graphify가 일부 기존 TS/TSX 파일의 구문을 완전히 해석하지 못한다는 경고를
  냈다. 그래프 갱신은 완료됐으며 Python 테스트 결과와는 무관하다.
