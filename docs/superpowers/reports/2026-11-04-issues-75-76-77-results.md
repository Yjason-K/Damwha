## 변경

- #75: 동일 회의의 자동저장을 QueryClient별 큐에서 직렬화한다. 실패 롤백은
  마지막으로 서버가 확인한 값을 사용하고, 이전 실패가 최신 초안을 건드리지
  않는다. 회의별 큐는 서로 독립적이다.
- #76: 종료 요청이 실패하거나 409로 봉인하지 못하면 재시도할 수 있게 한다.
  마지막 PCM과 오프셋을 확인 전까지 보존한다. 새 녹음 시작 전에 미확인
  종료를 재시도하고, 여전히 확인되지 않으면 서버 상태를 조회한다. 서버가
  종료·삭제를 확인한 경우만 이전 소유권을 놓는다. 회의 화면에서도 종료
  응답이 없는 한 레코더를 해제하지 않는다.
- #77: 화자 수정 트랜잭션이 회의 행을 먼저 잠그고 클러스터 처리 버전을
  검사한다. 발화 수정은 그 버전과 화자 라벨에만 적용한다.

## 회귀 재현

- #75: 이전 저장의 응답을 지연하거나 실패시키면 기존 코드에서 서버 본문과
  캐시가 각각 이전 값으로 돌아갔다. 세 개의 회귀가 수정 전 실패했다.
- #76: 종료 전송 실패 후 같은 Promise 재사용, 재동기화 실패, 미확인 세션
  교체를 각각 수정 전 재현했다. 리뷰에서 실제 HTTP로 확인한 자동 봉인 뒤
  409와 빈 회의 삭제 뒤 404도 서버 상태 확인 회귀에 포함했다. 최종 리뷰에서
  응답 유실 후 미확인 409를 받은 화면이 레코더를 해제하는 문제를 재현했고,
  종료 버튼의 재시도와 꼬리 전송을 검증하는 회귀 테스트를 추가했다.
- #77: 임시 Postgres와 실제 HTTP에서 이전 버전 발화까지 변경되고 오래된
  클러스터가 허용되는 사례를 수정 전 재현했다. 회의 행 잠금을 누락한
  중간 수정은 경합 테스트 두 건에서 실패해 잠금을 바로잡았다.

## 실제 경계 QA

- 격리 Chromium에서 실제 `NotePane`을 띄우고 합성 API의 첫 PUT을 보류했다.
  두 번째 입력을 저장한 뒤 첫 요청을 풀자 서버 저장값과 화면 모두
  `최신 초안`이었다. 첫 요청이 보류된 동안 서버 쓰기 수는 1, 완료 뒤 2였다.
  당시 임시 캡처를 생성했으나 재리뷰 시 파일이 남아 있지 않아 독립 확인은
  불가능했다. 운영 데이터는 사용하지 않았다.
- 화자 수정은 임시 Postgres의 실제 HTTP 경로와 트랜잭션 경합으로 검증했다.
- 녹음 종료는 실제 레코더·세션·화면 배선을 제어된 전송 및 가짜 오디오
  장치로 검증했다. 실제 마이크, Electron 번들, 장시간 실녹음은 실행하지 않았다.
