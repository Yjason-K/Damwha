## 후보 2 — uv venv --relocatable

### 2a. 기본값으로 만들면 무엇을 base로 잡는가
$ uv venv --relocatable --python 3.12 v1
  Using CPython 3.12.14 interpreter at: /opt/homebrew/opt/python@3.12/bin/python3.12
$ cat v1/pyvenv.cfg
  home = /opt/homebrew/opt/python@3.12/bin
  relocatable = true
$ ls -l v1/bin/python3.12
  python3.12 -> python -> /opt/homebrew/opt/python@3.12/bin/python3.12
$ mv v1 v2 && ./v2/bin/python3 -c 'import sys; print(sys.prefix, sys.base_prefix)'
  <옮긴 자리>/v2 /opt/homebrew/opt/python@3.12/Frameworks/Python.framework/Versions/3.12

### 2b. base를 후보 1의 배포본으로 지정해도
$ uv venv --relocatable --python <stage>/python/bin/python3.12 w1
$ cat w1/pyvenv.cfg
  home = /Users/.../experiments/electron-phase-0/stage/python/bin      <- 절대 경로
$ mv w1 w2 && ./w2/bin/python3 -c 'import sys; print(sys.prefix, sys.base_prefix)'
  <옮긴 자리>/w2   <stage>/python                                       <- base는 옛 자리

즉 --relocatable 이 상대화하는 것은 activate 스크립트뿐이고, pyvenv.cfg의
home은 그대로 절대 경로다. venv를 옮겨도 base가 따라오지 않으므로 결국
후보 1의 배포본을 번들 안에 두어야 하고, 그 위에 절대 경로 층이 하나 더
생긴다. (측정은 /private/tmp 아래 임시 디렉터리에서 했고 지웠다.)
