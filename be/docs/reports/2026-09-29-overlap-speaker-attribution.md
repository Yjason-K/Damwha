# 화자 겹침 구간 귀속 오류 조사 보고서

**작성일** 2026-09-29 · **범위** `worker/damwha_worker/pipeline/align.py`(`_segment_for`), `worker/scripts/eval_speaker_attribution.py`

## 요약

말이 빈틈없이 이어지는 대화에서 **B가 A의 말에 바로 이어 말하면 B의 첫마디가 A의 발언으로 기록되는** 증상을 클로바노트 전사와 대조해 측정했다. 4개 녹음(총 3시간 27분, 화자 5~7명) 기준으로 **화자가 바뀌는 지점마다 B의 첫 12글자 중 22.7%가 A에게 붙어 있었다.**

원인은 화자 분리(pyannote)가 아니라 그 뒤의 **단어→화자 배정 규칙**이었다. pyannote가 두 화자 구간을 겹치게 내놓으면, align은 겹친 자리의 단어를 **더 긴 구간의 화자**에게 줬다. 길게 말하던 A의 구간이 이어 말하는 B의 시작을 덮는 것이 겹침의 전형적인 모양이라, 이 규칙은 B의 첫마디를 체계적으로 A에게 넘겼다. 규칙을 **더 늦게 시작한 구간의 화자**로 바꿔 첫마디 누수를 **22.7% → 18.2%**, 누수 턴을 **363 → 287개(−21%)**로 줄였고 전체 귀속 정확도는 떨어뜨리지 않았다(89.80% → 89.85%).

## 1. 측정 방법

### 1.1 데이터

`~/Desktop/damwha_test`의 16 kHz mono wav 4개와, 같은 오디오를 클로바노트로 전사한 txt(`참석자 N mm:ss` 헤더 + 발언 텍스트)를 썼다.

| 녹음 | 길이 | 클로바 턴 | 클로바 화자 |
|---|---|---|---|
| 거짓말은 나쁜 것일까 | 53:54 | 325 | 6 |
| 운도 실력일까 | 47:43 | 262 | 5 |
| 제발 저에게 말할 시간을 주세요 | 43:27 | 319 | 7 |
| 포기하면 편해지지 않을까요 | 61:55 | 631 | 6 |

**클로바노트도 ASR + 화자 분리 결과다.** 정답지가 아니라 비교 기준으로 쓰며, 아래 수치는 변형 간 상대 비교로만 읽는다.

### 1.2 채점

`eval_diarization.py`는 사람이 라벨링한 RTTM(시간 구간)이 있어야 하고, `eval_stt.py`는 텍스트만 본다. 사용자가 실제로 보는 "이 문장이 맞는 사람 밑에 있는가"를 재는 도구가 없어서 `scripts/eval_speaker_attribution.py`를 새로 만들었다.

1. **cache** — 워커와 같은 순서(VAD → pyannote → ECAPA → Whisper turbo, VAD 구간만 전사)로 모델을 한 번 돌리고 align 입력을 JSON으로 저장한다. pyannote의 regular 출력과 exclusive 출력을 둘 다 저장한다.
2. **score** — 캐시에서 align 변형별로 발언을 다시 만들고, 우리 텍스트와 클로바 텍스트를 **글자 단위로 정렬**한다(한글을 자모로 풀어 edlib NW 정렬, 공백·문장부호 제외). 일치한 글자마다 우리 화자와 클로바 화자를 비교한다. 화자 라벨 대응은 DER과 같이 헝가리안 1:1 매핑으로 정한다.

| 지표 | 뜻 |
|---|---|
| attr | 일치한 글자 중 화자가 맞은 비율 (전체 귀속 정확도) |
| **head→prev** | 클로바에서 A→B로 화자가 바뀔 때, B의 첫 12글자 중 A에게 붙은 비율 — **이번 증상 그 자체** |
| tail→next | A의 마지막 12글자 중 B에게 붙은 비율 (반대 방향) |
| turn | 클로바 턴 중 다수결 화자가 맞은 비율 |
| leaks | B의 첫마디 절반 이상이 A에게 간 턴 수 |

## 2. 원인

### 2.1 사례 — 「거짓말은 나쁜 것일까」 00:46

클로바 기준으로 00:46에 참석자 2가 "물 없이 먹는 거 쉽지 않아"라고 말한다. 이 구간의 pyannote(regular) 출력은 다음과 같았다.

```
SPEAKER_03  46.27s ─────────────────────────── 49.96s
SPEAKER_01          46.71s ──────── 47.67s
Whisper       "물 없이 먹는 거 쉽지 않아요"  46.14–47.64s
```

**pyannote는 두 번째 화자를 정확히 잡았다.** SPEAKER_01의 구간이 참석자 2의 발언과 시간상 정확히 겹친다. 그런데 단어들의 중점이 두 구간 모두에 들어가자 `_segment_for`는 더 긴 SPEAKER_03을 골랐고, 참석자 2의 말은 SPEAKER_03(앞 화자)의 발언에 합쳐졌다.

### 2.2 규칙의 내력

"더 긴 구간이 이긴다"는 규칙은 `f1f6586`(백채널 세그먼트가 본 화자의 단어를 빼앗는 문제 수정)에서 들어왔다. A가 길게 말하는 도중 "맞아" 같은 짧은 호응 B가 끼면, 겹친 자리의 A 본문이 B에게 가는 것을 막으려는 의도였다.

하지만 겹침의 흔한 모양은 그 반대다. 대화가 빈틈없이 이어지면 pyannote는 **앞 화자 구간의 끝을 다음 화자의 시작 위로 늘려** 내놓는 경우가 많다. 이때 겹친 자리의 단어는 대개 **새로 말을 시작한 B**의 것인데, 길게 말하던 A의 구간이 더 기니 B의 첫마디가 A에게 갔다. 백채널 쪽 위험은 같은 커밋의 `_smooth_backchannels`(이후 임베딩 판정자 추가)가 따로 다루고 있어, 배정 규칙까지 A 편을 들 필요가 없었다.

### 2.3 이 수정으로 못 고치는 원인

모든 누수가 배정 규칙 때문은 아니다. 같은 녹음 00:37~00:46에서는 pyannote가 **세 사람의 빠른 주고받기를 SPEAKER_03 한 명으로** 내놓았다(37.6~45.9s 연속 구간). 화자 분리 단계에서 전환 자체를 놓친 경우라 align이 할 수 있는 일이 없다. 수정 뒤에도 남은 누수 234턴은 대부분 이 유형으로 보인다(§4).

## 3. 개선

### 3.1 시도한 변형

모두 같은 캐시(같은 pyannote·Whisper 출력)에서 align만 바꿔 쟀다.

| 변형 | 내용 |
|---|---|
| longest | 기존 규칙 — 겹치면 더 긴 구간 |
| **latest (채택)** | 겹치면 **더 늦게 시작한 구간** |
| shortest | 겹치면 더 짧은 구간 |
| exclusive | 기존 규칙 그대로, pyannote의 exclusive 출력(겹침 없음) 사용 |
| no_arb | 임베딩 판정자 끄기 (대조군) |

파일 1에서 먼저 비교했다(첫마디 누수 / 턴 정확도).

| 변형 | head→prev | turn |
|---|---|---|
| longest | 22.7% | 70.6% |
| shortest | 19.6% | 75.8% |
| exclusive | 20.9% | 73.1% |
| **latest** | **15.9%** | **77.3%** |
| latest + 판정자 끔 | 20.9% | 72.3% |

`shortest`는 전체 귀속 정확도를 깎았고(0.914), `latest`는 모든 지표가 올랐다. 판정자를 끄면 이득 대부분이 사라진다. `latest`가 백채널 쪽에서 새로 만드는 오류를 판정자가 되돌리고 있다는 뜻이고, 두 장치가 함께 있어야 성립하는 수정이다.

### 3.2 변경 내용

`_segment_for`에서 겹침 시 선택 기준을 `max(..., key=길이)` → `max(..., key=시작 시각)`으로 바꿨다. 기존 테스트(백채널 B가 A보다 **먼저** 시작해 겹치는 경우 A가 이김)는 새 규칙에서도 그대로 성립해 기대값을 바꾸지 않았고, 이름만 규칙에 맞게 고쳤다. 증상을 재현하는 테스트 `test_next_speaker_opening_inside_previous_segment_goes_to_next`를 추가했다. 이 테스트는 옛 규칙에서 실패하고 새 규칙에서 통과한다. 워커 전체 스위트 858개 통과.

**match 수치에 대한 주의.** `current`의 match가 약 1%p 낮은데, 텍스트를 잃은 것이 아니다. 발언은 시작 시각 순으로 정렬되므로 단어의 화자가 바뀌면 겹친 발언들의 텍스트 순서가 달라지고, 순서에 민감한 글자 정렬이 그만큼 덜 맞는다. 단어 수는 같다.

## 5. 남은 과제

1. **화자 전환 자체를 놓치는 경우**(§2.3)가 남은 누수의 주력이다. pyannote 파이프라인 파라미터(segmentation `min_duration_off`, clustering threshold)를 이 스크립트로 조정해 볼 수 있다.
2. **exclusive와의 조합.** exclusive 출력은 전체 정확도를, latest 규칙은 첫마디를 개선한다. regular 출력의 짧은 겹침 구간 정보를 살리면서 exclusive 경계를 쓰는 방식을 시험할 만하다.
3. **Whisper 단어 타임스탬프.** 턴 경계 근처에서 길이 0인 단어(`41140–41140`이 4개 연속 등)가 보인다. 타임스탬프가 틀리면 배정 규칙이 옳아도 단어가 엉뚱한 구간에 떨어진다.
4. **새로 생긴 누수 53개**의 유형 분석. 백채널 판정자가 놓친 경우인지 확인이 필요하다.

## 6. 재현

```bash
cd be/worker
uv run python scripts/eval_speaker_attribution.py cache \
    --outdir /tmp/attr ~/Desktop/damwha_test/*.wav        # 4개(3시간 27분) 약 1시간
uv run --with edlib python scripts/eval_speaker_attribution.py score \
    --cache /tmp/attr --ref-dir ~/Desktop/damwha_test --leaks
```

`score`는 변형당 녹음 1개에 1~5분 걸린다(대부분 임베딩 판정자의 ECAPA 호출). 기본 변형은 `longest,current,exclusive`이고 `--variants`로 고른다.
