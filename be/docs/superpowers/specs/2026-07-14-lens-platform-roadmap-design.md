# 전역 회의 렌즈 플랫폼 — 작업 분할 설계

> 상태: 승인됨 · 작성일: 2026-07-14

## 1. 목적

좌측의 “모든 회의” 탭을 전역 렌즈 대시보드로 완성한다. 대시보드는 모든
회의의 액션아이템, 결정사항, 주제·키워드, 약속·책임을 모아 보여 주며, 각
항목은 원본 발언과 오디오 시점으로 되짚을 수 있어야 한다.

이 범위는 데이터 영속화, 비동기 AI 추출, 전역 UI, 저장 검색이라는 서로 다른
변경 축을 포함한다. 한 계획으로 구현하지 않고, 아래 네 작업을 각각
`brainstorming → spec → plan → execute` 순서로 완료한다.

## 2. 확정된 제품 원칙

- 액션아이템, 결정사항, 주제·키워드, 약속·책임을 모두 지원한다.
- 액션·결정·약속은 회의 처리 완료 뒤 자동 추출하고, 사용자는 재추출을 요청할 수 있다.
- 항목 추가·수정·삭제·완료 상태는 영구 저장한다.
- 재추출은 사용자 추가, 사용자 수정, 완료 상태를 덮어쓰지 않는다.
- 모든 AI 추출 항목은 가능한 경우 하나 이상의 원본 발언 근거에 연결한다.
- 주제·키워드는 별도 AI 분류가 아니라 기존 검색 인프라를 사용하는 저장 검색이다.

## 3. 공통 목표 아키텍처

`lens_item`은 액션·결정·약속의 영속 항목이며, 출처(`ai`, `user`, `edited`),
완료 상태, 담당 화자, 기한, 신뢰도, 사용자 수정 여부를 가진다.
`lens_evidence`는 항목과 발언을 연결해 발언 점프를 가능하게 한다.
`lens_extraction_run`은 처리 버전별 추출 작업의 상태·모델·오류를 기록한다.
주제 렌즈는 `saved_lens`에 검색어·필터 정의를 저장한다.

자동 추출은 NestJS 요청 안에서 실행하지 않는다. 기존 Postgres 작업 큐와 Python
워커에 `extract_lenses` 작업을 추가하고, LLM 출력은 JSON 스키마 검증을 통과한
경우에만 저장한다. 대시보드와 회의별 인사이트는 NestJS의 렌즈 조회 API를 통해
동일한 영속 데이터를 읽는다.

## 4. 분할 작업

### 작업 1 — 렌즈 기반 서비스 — 완료 (2026-07-14)

**범위:** DB 마이그레이션, 렌즈 항목·근거·실행 이력의 도메인 모델, 병합 규칙,
조회·변경·재추출 요청 API 계약.

**제외:** 실제 LLM 호출 및 대시보드 UI.

**완료 결과:** 사용자 변경을 보존하는 병합 규칙, CRUD/조회 API, 근거 연결,
cursor 페이지네이션, 화자 삭제 정합성(`assignee_speaker_id` null 처리)이 구현·테스트됐다.
추출 워커가 쓸 안정적인 저장 계약이 존재한다. 구현 커밋은 `99d09c4`–`006ae4d`,
후속 정합성 수정은 `9318cef`이다.

### 작업 2 — 자동 렌즈 추출 워커 — 완료 (2026-07-15)

**범위:** `extract_lenses` 작업 계약, 처리 완료 후 자동 enqueue, 로컬 LLM 추출,
구조화 출력 검증, 재시도와 수동 재추출.

**대상:** 액션아이템, 결정사항, 약속·책임.

**제외:** 전역 대시보드 UI 및 주제 저장 검색.

**완료 기준:** 정상 회의가 자동 추출되고, 실패가 작업 상태로 관찰되며,
재추출이 작업 1의 보존 규칙을 지킨다.

**완료 결과:** `extract_lenses` job 계약, 수동 재추출 API와 추출 상태 조회,
OpenAI 호환 로컬 LLM 클라이언트, 소유권·버전 가드 병합, 처리 완료 시 자동
enqueue가 구현·테스트됐다. 구현 커밋은 `f931d7a`–`518e809`이다.

### 작업 3 — 모든 회의 전역 대시보드 — 완료 (2026-07-21)

**범위:** 현재 준비 중인 전역 LensView를 실제 대시보드로 교체한다. 렌즈 탭,
기간·화자·회의·상태 필터, 완료 표시, 출처, 추출 상태, 근거 발언 점프를 제공한다.

**제외:** 저장 검색 정의를 만들고 편집하는 UI.

**완료 기준:** 액션·결정·약속 항목을 전역에서 조회·필터·완료 처리하고, 각 근거
발언의 회의·오디오 시점으로 이동할 수 있다.

**완료 결과:** 설계는 `2026-07-21-lens-global-dashboard-design.md`.
BE는 전역 추출 상태 집계 엔드포인트 `GET /lenses/extraction-status`를 추가했고
(커밋 `630051d`), FE는 `features/lens/` 모듈에 무한 스크롤 목록, kind 탭,
완료·기간·화자·회의 필터, 낙관적 완료 토글, 추출 상태 배너와 회의별 재시도,
근거 발언 점프를 구현해 placeholder `LensView`를 대체했다
(커밋 `408b03b`–`3d1e2e1`).

**설계 대비 확정된 차이:**
- 완료 필터는 BE `completion_status`가 단일값(`open`|`done`)이라 "열림|완료"
  세그먼트로 만들었다(열림+완료 동시 조회 없음).
- 근거 발언 점프는 회의뷰 전환 + 발언 하이라이트까지이며 오디오 seek는 하지
  않는다(스펙 비범위). 근거 발언이 재처리로 사라진 historical 항목은 토스트로
  안내한다.

**검증(2026-07-21):** FE `pnpm vitest run` 82/82, `tsc -b`·`pnpm build`·
`pnpm lint` exit 0. BE `npm test` 27스위트 195/195, `tsc --noEmit` exit 0.

### 작업 4 — 주제·키워드 저장 렌즈

**범위:** 기존 검색 API 위의 `saved_lens` CRUD, 저장 검색 결과 조회, 전역
대시보드의 주제 탭 및 관리 UI.

**제외:** 새로운 임베딩 모델 또는 별도 토픽 분류 모델.

**완료 기준:** 사용자가 검색 조건을 주제 렌즈로 저장·수정·삭제하고, 전역에서
최신 검색 결과를 보며 발언 점프할 수 있다.

## 5. 실행 순서와 의존성

```text
작업 1: 렌즈 기반 서비스
  ├─> 작업 2: 자동 렌즈 추출 워커
  │     └─> 작업 3: 모든 회의 전역 대시보드
  └─> 작업 4: 주제·키워드 저장 렌즈
```

작업 4는 작업 1 이후 작업 2·3과 병렬로 계획할 수 있지만, 공유 작업 공간에서의
충돌을 피하기 위해 구현 순서는 작업 3 뒤로 둔다. 각 작업은 직전 의존 작업이
검증되어 병합된 뒤에 시작한다.

## 6. 공통 품질 조건

- AI 출력의 종류, 화자 ID, 발언 ID, 기한은 서버 측에서 검증한다.
- 실패·진행 중 추출은 대시보드에서 명시적으로 표시하고 재시도 경로를 제공한다.
- 회의 재처리나 삭제 뒤에도 근거와 렌즈 항목의 정합성을 보장한다. 근거가
  사라진 보존 항목은 삭제하지 않고 “근거 확인 필요”로 표시한다.
- API·워커·UI 경계마다 단위 또는 E2E 테스트를 추가한다.

## 7. 비범위

- 팀 공유·권한 모델·외부 내보내기
- 발언량이나 참석률 분석
- 별도 토픽 분류/임베딩 모델
